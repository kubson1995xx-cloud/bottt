# APEX Naval Command — Windows x64

**Windows desktop-local — bez ręcznego logowania. Kandydat oczekuje niezależnego odbioru.** Wymagane są testy dokładnego EXE: pierwszy start, aktualizacja poprzedniego profilu, przeglądarka bez podawania poświadczeń i restart. Sprawdź osobne wyniki dla dokładnego SHA źródeł i ZIP-a. Hosted Windows Server nie jest fizycznym Windows 11 Pro użytkownika.

## Klucze OKX i test salda DEMO — bez START

1. **Dodaj konto**: „APEX — konfiguracja OKX” ma tylko cztery pola metadanych. Ich zatwierdzenie **nie zapisuje konta ani klucza**.
2. Następne okno to **„APEX — chroniona zgoda OKX” na chronionym pulpicie Windows**. Wpisujesz hasło tego samego użytkownika **Windows**, nie hasło OKX. Nie wpisuj go w przeglądarce. Windows Hello/PIN/karta nie mają potwierdzonej obsługiwanej ścieżki; nie obniżaj polityk ani nie zastępuj zgody kliknięciem „Tak”.
3. Dopiero po tej zgodzie otwiera się **„APEX — lokalny klucz OKX”**: trzy maskowane pola **API Key**, **Secret Key**, **Passphrase**. Wpisz je ręcznie lokalnie, nie używaj czatu, URL, argumentów, logów, screenshotów ani plików tekstowych. Dane muszą pochodzić z wybranego środowiska.
4. Sukces pełnego zapisu ma kod `SAVED_KEY_CONFIG_RUNTIME_VERIFIED_STOP_NOT_CONNECTED`: odczytano ponownie CurrentUser DPAPI, dokładną konfigurację i binding runtime. **Sprawdź zapis klucza lokalnie (bez sieci)** ponawia tylko lokalny odczyt i pokazuje `SAVED_KEY_CONFIG_RUNTIME_VERIFIED`. Po restarcie sprawdź ponownie, zanim użyjesz sieci.
5. `METADATA_ONLY_NO_KEY` = jest konfiguracja, brak katalogu klucza; `CIPHERTEXT_PRESENT_NOT_VERIFIED` = plik istnieje, jeszcze bez weryfikacji DPAPI; `INCOMPLETE_STORE_PRESERVED` / `UNBOUND_OR_PARTIAL_STORE_PRESERVED` / kod `PRESERVED` = niepełny lub niepowiązany stan, bez automatycznej naprawy. **Nie usuwaj danych i nie nadpisuj/reseeduj.** Nie wysyłaj prywatnych plików do diagnozy.
6. `APPROVAL_TIMEOUT_DISMISS_WINDOWS_PROMPT` to timeout, **nie anulowanie**. Zamknij poprzednie okno Windows. `APPROVAL_USER_CANCELLED` oznacza anulowanie, `AUTHENTICATION_REFUSED` odmowę hasła, `UNPACK_UNSUPPORTED_METHOD` nieobsługiwaną metodę, `PROMPT_OS_ERROR_WIN32_N` błąd natywnego API. Zachowaj tylko etap i kod liczbowy. Panel pokazuje oczekiwane następne okno; brak błędu nie oznacza zapisu.
7. Wybierz **DEMO**, pozostań rozłączony/STOP i kliknij **Test połączenia DEMO / odczytaj saldo — tylko odczyt**. Test jest jednorazowy, maksymalnie 35 s, nie uruchamia się po zapisie ani starcie programu. **STOP** anuluje oczekiwanie. Nie używaj Observe, bazy, Execute ani START do samego testu.
8. Czytnik wymaga istniejącej ścisłej polityki `read_only` **bez Trade**, przypisanego IP i bezpiecznego cash SPOT. Klucz z Trade jest bezpiecznie odrzucany (`UnsafeAccountConfig`); test nie zmienia jego uprawnień ani nie nadpisuje go. To nie dopuszczenie klucza do handlu. Dla już zapisanego klucza handlowego nie usuwaj go w celu przejścia tego testu.
9. `DEMO_TEST_OBSERVED_READ_ONLY_STOP` pokazuje uwierzytelniony UID, `OkxDemo`, walutę, **Cash**, **Available** i czas obserwacji w `demoRead`. Brak waluty/kwoty jest jawnie nieznany, nigdy wymyślone zero. To **obserwacja, nie P&L, baza kapitału ani gotowość do handlu**. Błędy publicznego czasu, prywatnego auth i bindingu UID mają osobne kody. LIVE i niezgodne credentials są blokowane bez prywatnych wysyłek.

**Granica odbioru:** hosted Windows pozwala sprawdzić prawdziwy natywny formularz i DPAPI oraz timeout chronionej zgody. Nie dowodzi pomyślnego wpisania własnych poświadczeń Windows na chronionym pulpicie, pełnego enrollment na Twoim Windows11 ani rzeczywistego prywatnego OKX DEMO. Te trzy dodatnie kryteria pozostają lokalnym odbiorem użytkownika, bez przekazywania sekretów i bez jakiejkolwiek transakcji. Nie traktuj metadanych/Cancel jako ich zaliczenia.

## START po poprawce interfejsu OKX / Naval

- Zatrzymaj starą instancję świadomie, zachowując prywatne dane. Rozpakuj **cały nowy ZIP do nowego folderu** i uruchom nowe `APEX-Desktop\ApexDesktop.exe`, nie stary skrót. Nie kasuj `%LOCALAPPDATA%\APEX Trading AI`.
- Operator OKX jest teraz osobnym panelem w normalnym układzie treści, bez zasłaniania przez lewy pasek. Przycisk **Operator OKX ↑** wraca do niego; **Wróć do widoku Naval** przewija do bieżącego widoku. Stary polski panel i pięć widoków pozostają dostępne.
- **Dodaj konto** otwiera osobne rzeczywiste okno Windows „APEX — konfiguracja OKX”. Gdy przeglądarka pozostała z przodu, sprawdź pasek zadań lub **Alt+Tab**. Nie wpisuj kluczy ani hasła w stronę WWW. Puste/niepoprawne metadane pokazują błąd w otwartym formularzu; **Anuluj** nie zapisuje konta.
- Brak konta / połączenia / własnego stanu do redukcji to jawny powód niedostępności odpowiednich poleceń, nie uszkodzony przycisk. Przy błędzie odczytu użyj **Odśwież status**. Odpowiedź `BASELINE_REQUIRED` lub odmowa nie jest sukcesem połączenia ani START. Nie ponawiaj niepewnego wyniku mutacji w ciemno.
- Nagłówek „Naval: tylko odczyt historii” opisuje **syntetyczne widoki Naval**, nie osobnego operatora OKX. Żadnych syntetycznych sald nie uznajemy za rzeczywiste saldo OKX.
- Dowód otwarcia/obsługi metadanych nie jest dowodem pomyślnego chronionego uwierzytelnienia Windows ani zapisu maskowanych sekretów. Pozytywny etap zgody, provisioning i prywatne DEMO pozostają osobnymi lokalnymi kryteriami; nie obchodź ich.

## Rozpakowanie i start

1. Porównaj SHA-256 pliku `APEX-NAVAL-COMMAND-Windows-x64.zip` z otrzymanym z zaufanego źródła plikiem `.zip.sha256` (`Get-FileHash -Algorithm SHA256`). Suma i manifest nie są podpisem wydawcy. Pliki nie są podpisane: nie omijaj bezrefleksyjnie SmartScreen ani ostrzeżeń systemu; przy nieznanym źródle przerwij.
2. Rozpakuj **cały ZIP** do nowego lokalnego folderu. Nie uruchamiaj z wnętrza ZIP i nie przenoś samego EXE. Zachowaj `wwwroot`, `presentation`, dokumentację i weryfikator.
3. Główne wejście: dwuklik `APEX-Desktop\ApexDesktop.exe`. `Uruchom APEX.cmd` jest tylko opcjonalnym skrótem. Pakiet self-contained zawiera .NET 8; odbiorca nie instaluje .NET SDK, Node, Pythona, Visual Studio ani osobnego VC++ redistributable. Opcjonalne narzędzia weryfikacji/budowania nie są zależnością aplikacji. MT5 wymaga osobnego MetaEditora wyłącznie do użycia opcjonalnego źródła mostu.
4. Nowy, pusty katalog danych Windows otrzymuje prywatny profil `windows-local-presentation-v1`. **Nie wpisujesz loginu ani hasła i nie zatwierdzasz okna poświadczeń.** Ten sam start bez logowania działa na kompletnym, prawidłowym profilu prezentacyjnym poprzedniego wydania, bez usuwania ani resetowania danych.
5. Po poprawnym związaniu portu aplikacja prosi domyślną przeglądarkę o otwarcie `http://127.0.0.1:5077/?view=naval` (lub ustawionego portu). W trybie desktop-local następuje od razu stałe przekierowanie `/naval/`, bez Basic popup. Jeżeli system nie otworzy przeglądarki, otwórz ręcznie lokalny adres bez sekretu pokazany w komunikacie. `/` bez query pozostaje starym polskim panelem. Reader Bearer ma tylko dwa GET API, nie dostęp do dokumentów/UI.

Opcjonalny podgląd prywatnych poświadczeń do **jawnie chronionego trybu/API**, bez uruchamiania hosta i rotacji (nie jest potrzebny do zwykłego startu):

```powershell
& '.\APEX-Desktop\ApexDesktop.exe' --show-local-access
```

Dla własnego katalogu dodaj `--data 'C:\pełna\prywatna-ścieżka'`. Nie przekazuj hasła w argumentach. Weryfikacja plików: `powershell -NoProfile -File .\Sprawdz-Pakiet.ps1 -Pakiet .` (jeśli lokalna polityka pozwala uruchomić zaufany skrypt; nie obniżaj jej w ciemno).

## Dane, aktualizacje i bezpieczna odmowa

Domyślny katalog danych: `%LOCALAPPDATA%\APEX Trading AI`. Precedencja: `--data`, następnie `APEX_DATA_DIR`, następnie domyślny KnownFolder. Dane są **poza całym pakietem**, chronione natywnymi ACL dla bieżącego użytkownika, SYSTEM i Administratorów. Poświadczenia webowe przechowuje CurrentUser DPAPI oraz mapa skrótów; nie są to klucze brokera. Nie wysyłaj konfiguracji, map, plików DPAPI ani prywatnych logów. Pliki natywne, jeśli są potrzebne, rozpakowuje mechanizm .NET poza ZIP-em. W tym wariancie .NET 8 kod CoreCLR/JIT/hostingu jest statycznie związany z EXE: smoke wiąże sekcje wykonywalne z rzeczywistym szablonem hosta SDK, sprawdza pochodzenie załadowanych modułów i ACL katalogu ekstrakcji oraz raportuje faktyczną liczbę rozpakowanych plików (również zero).

Istniejąca poprawna konfiguracja i własne profile pozostają zachowane, również `NavalRead` wyłączone. Rozpoznany kompletny profil prezentacyjny Windows dostaje desktop-local wyłącznie w pamięci procesu; pliki konfiguracji, mapy i DPAPI nie są migrowane ani nadpisywane. Własne chronione konfiguracje bez znacznika prezentacji pozostają chronione. Jawne `NavalRead.RequireAuthentication=true` zachowuje Basic Operator / Bearer Reader również dla profilu prezentacji. To tryb legacy, a nie portal bezpieczny dla roli Reader. Nie przenoś poświadczeń między użytkownikami: DPAPI wiąże je z kontem Windows. Nie usuwaj ani nie resetuj danych po błędzie.

- `HOST_DATA_PATH_INVALID`, `HOST_DATA_PERMISSIONS_INVALID`, `HOST_DATA_UNAVAILABLE`: wybierz nowy prywatny lokalny katalog poza wydaniem albo zleć administratorowi analizę ścieżki/ACL, linków i miejsca na dysku. **Nie** nadawaj Everyone/Users pełnego dostępu i nie obchodź kontroli. Program nie naprawia niebezpiecznych istniejących ACL.
- `HOST_LOCAL_SETUP_INCOMPLETE` lub problem DPAPI: zachowaj wszystkie pliki i kopię zapasową. Przerwanej inicjalizacji nie leczy się kasowaniem map/konfiguracji. Użyj tego samego konta Windows i zweryfikowanego kompletu danych; odzyskanie wymaga świadomej diagnozy.
- `HOST_ALREADY_RUNNING`: korzystaj z istniejącej instancji; nie usuwaj blokady uruchomionego procesu.
- `HOST_HTTP_BIND_FAILED`: sprawdź własny proces/port, bez przechodzenia na obcy serwer. Program nie szuka innego portu automatycznie. Opcjonalny zajęty TCP mostu daje degradację, nie oznacza poprawnego połączenia z platformą.

Aktualizuj ręcznie do **nowego folderu**, po finansowym STOP, sprawdzeniu pozycji i zakończeniu własnego procesu. Zachowaj cały prywatny katalog danych z ACL; backup również musi być prywatny. Nie usuwaj rejestrów sygnałów, limitów, planów ani latch STOP. Nie kopiuj prywatnych danych do wydania.

## Granica zaufania desktop-local

Brak hasła oznacza świadome zaufanie do **procesów/użytkowników tego samego komputera mających dostęp do loopback**. To nie izolacja między użytkownikami Windows ani tryb dla współdzielonego/niezaufanego komputera. Program nadal wiąże tylko `127.0.0.1`, kontroluje Host (DNS rebinding), Origin i Fetch Metadata. Obce strony, formularze cross-origin i preflight nie mogą sterować API; mutacje wymagają JSON oraz niestandardowego nagłówka anty-CSRF `X-Apex-Local: 1`. Nie jest on hasłem ani prawem do START. Nie publikuj portu przez proxy/LAN/Internet. Dla wymaganej izolacji użyj jawnie chronionego trybu, nie wyłączaj ACL/DPAPI. Rola Reader pozostaje API-only; podane Bearer credentials nie są podnoszone do Operatora.

## OKX — konfiguracja i polecenia (kandydat inżynierski, nie gotowy trader)

Sekcja **OKX — lokalny operator** jest dostępna nad pięcioma widokami Naval i w oryginalnym panelu `/`. Zwykły start nadal nie pyta o login, nie otwiera kluczy OKX i nie wykonuje prywatnych żądań. Dane historyczne pięciu widoków nie są statusem rachunku OKX; rzeczywisty status rachunku i zobowiązania czytaj w sekcji OKX.

1. **Dodaj konto — natywny formularz**: w oknie Windows wybierz jawnie `DEMO` albo `LIVE` (bez domyślnego LIVE), podaj nazwę zakresu, główny UID i rzeczywistą walutę kwotowaną. Obsługiwany jest jeden dedykowany główny rachunek na środowisko, cash SPOT ≤1×; bez subkont, pożyczek, margin, futures i perps. Zapis nowego zakresu nie naprawia ani nie nadpisuje poprzednich danych.
2. Potwierdź lokalną operację na chronionym pulpicie Windows **własnymi poświadczeniami Windows**, nie kluczem OKX. Provider sprawdza SID bieżącego użytkownika i sesję interaktywną. Anulowanie, inny użytkownik, sesja nieinteraktywna lub brak obsługiwanej metody uwierzytelnienia odmawiają zgody. Konta wyłącznie passwordless/Windows Hello nie mają tu jeszcze potwierdzonej alternatywy; nie zastępuj chronionej zgody zwykłym kliknięciem „Tak”. Nie wpisuj hasła Windows w panelu WWW ani w czacie.
3. Dopiero w osobnym **lokalnym, maskowanym formularzu Windows** wpisz API key, Secret key i Passphrase z wybranego środowiska OKX. Nigdy nie wklejaj ich do przeglądarki, URL, argumentów EXE, zrzutów ekranu ani logów. Magazyn używa istniejącego CurrentUser DPAPI i prywatnych ACL. Po anulowaniu nie powstaje nowe konto. Przy błędzie zapisu zachowaj częściowy stan do diagnozy; nie próbuj go nadpisywać.
4. Wybierz zakres w panelu i naciśnij **Połącz — chronione Observe**. To oddzielne świadome zezwolenie na prywatny odczyt. Native kontrola uprawnień wymaga rzeczywistej weryfikacji klucza i dokładnego IP; nie składaj oświadczenia o braku transferów/pożyczek/earn/wypłat, jeśli OKX nie daje takiego dowodu. Samo `trade` ani poprawny GET nie dowodzą właściwego zakresu uprawnień. Brak dowodu oznacza `PERMISSION_SCOPE_UNPROVEN`.
5. **Zatwierdź rzeczywistą bazę** zbiera nową uwierzytelnioną obserwację przed chronioną zgodą: rzeczywista gotówka, waluta, UID, instrumenty i opłaty. To nie syntetyczny kapitał. Zgoda ma krótki budżet świeżości; po zbyt długim oczekiwaniu może odmówić. Istniejącego właściciela nigdy nie reseedujemy. Obce aktywa, zobowiązania, niepewne zlecenia i błędy historii wymagają wyjaśnienia, nie resetu.
6. **Uzbrój Execute** jest osobne od **START**; uzbrojenie nie wysyła zlecenia. STOP, rozłączenie, restart i zmiana rachunku cofają zgody. Aby zmienić środowisko/rachunek, najpierw rozłącz poprzedni. Wszystkie polecenia i scheduler używają tego samego istniejącego właściciela rachunku — nie osobnego salda panelu.
7. **START produkcyjny ma wbudowaną politykę warunkową `OKX-CASH-FOK-QUOTE-FEE-CONDITIONAL-v1`**, wspólną dla DEMO/LIVE. Wymaga uwierzytelnionego `feeType=1` (opłaty zawsze w rzeczywistej walucie quote), wyłączonych pożyczek i cash Spot-mode/poziom 1. `feeType=0`, opłata bazowa/inna waluta, rebate lub niezgodny katalog nie są obsługiwane do otwierania. Obsługiwany katalog to odkryte prywatnie pary aktywów strategii z tym samym taker fee i rzeczywistym quote; musi zawierać BTC. Nie zakładamy, że każda para/konto jest dopuszczone. Świeże publiczne książki `BASE-USD` i `BASE-USDT` są dodatkowo wymagane do kontroli prywatnych maksimów w ich własnych jednostkach — nie zakładamy parytetu USD/USDT/USDC. Brak referencji, nieznany limit/jednostka, regresja czasu źródła, stare/przyszłe/skrzyżowane kwotowanie lub przekroczenie tick/lot/minimum/maksimum odmawia przed wysłaniem.

   Wejście to bazowo wymiarowany, cenowo ograniczony FOK z żądanym TP i SL. **Ochrona powstaje dopiero po fill i może zawieść. ACK ani samo żądanie TP/SL nie oznaczają ochrony.** RUNNING wymaga obserwacji dokładnego własnego OCO, obu triggerów last/market oraz własnego stanu netto. Wyjście strategii obserwuje anulowanie dokładnej ochrony przed osobną sprzedażą FOK. Po anulowaniu i nieudanej/Unknown sprzedaży **może pozostać niechroniona reszta bez gwarantowanego czasu odzyskania ani maksymalnej straty**. Nie obiecujemy ceny wykonania stopa.

   Rozliczenie oznacza zgodność indywidualnych fills/opłat quote, bills, końcowego zlecenia i dokładnych sald w zamkniętej obserwacji. Nie jest obietnicą, że broker nigdy nie skoryguje opłaty; późniejsza sprzeczność zatrzymuje dopuszczenie zamiast cichego przepisania lub podwójnego księgowania. Anulowany bez fill FOK zwalnia hold dopiero po takim potwierdzeniu.

   **Odzyskiwanie:** przeczytaj `inventory` (dokładna rezerwacja/ilość/stan) i `obligations`. Reconciliation trwa przy STOP, ale nie handluje. Po świeżym uzbrojeniu Execute wybierz dokładny własny stan i naciśnij **Redukuj wybrany własny stan** — to osobne polecenie transakcyjne bez START, nigdy sprzedaż całego salda. Nierozwiązane ancestry, obce/konkurujące zlecenie, nieznana ilość, dust lub Unknown odmawiają redukcji. Jeśli poprzednia sprzedaż została jednoznacznie anulowana bez fill albo na pewno nie została wysłana, dopiero jawne następne polecenie otrzymuje nową tożsamość operacji. Nie ma automatycznego ponawiania mutacji. Pozostałego Unknown nie wolno duplikować. W razie braku bezpiecznej redukcji sprawdź ochronę i zlecenia bezpośrednio w OKX; nie kasuj stanu APEX.
8. **STOP** blokuje nowe ryzyko; **Emergency Stop** zatrzaskuje STOP istniejącego właściciela i pokazuje nierozwiązane zobowiązania. Żaden z tych komunikatów nie potwierdza automatycznej likwidacji, anulowania ochrony ani sprzedaży całego salda. `EMERGENCY_STOP_NO_OPEN_OWNER` oznacza brak otwartego właściciela, a nie zapisany finansowy latch. `obligationsKnown=false` / `obligations=null` oznacza **nieznany** stan zobowiązań, nigdy „brak zobowiązań”. Po anulowaniu lub upływie czasu zgoda jest nieważna; chronione okno Windows może nadal wymagać ręcznego zamknięcia i do tego czasu nie otwieramy kolejnej zgody. Sprawdź rzeczywiste zlecenia/ochronę w OKX. Nigdy nie ponawiaj niepewnego otwarcia w ciemno.

Natywne testy syntetyczne nie łączą rachunków ani nie składają zleceń. Pozytywne przyjęcie własnych poświadczeń Windows i rzeczywisty prywatny DEMO flow wymagają lokalnego, osobno uprawnionego odbioru; sama zielona paczka ich nie zastępuje. Agent nie otrzymał zgody na prywatne połączenie ani jakąkolwiek transakcję. LIVE pozostaje domyślnie OFF; blokady REAL/Crypto cTrader i MT5 pozostają bez zmian.

## Ograniczenia i handel

Pięć widoków Naval i opcjonalne 3D przedstawiają dołączony **historyczny syntetyczny checkpoint**, wyprodukowany podczas budowy. `UNKNOWN`, `NOT_CONFIGURED`, brak brokerskiego P&L i historyczna świeżość są celowe. To nie rachunek, rynek na żywo, wynik inwestycyjny, sygnał ani zgoda na START. Nowy profil ma **zero kont runtime**, bez automatycznego START i bez automatycznego pobierania wiadomości. Wszystkie sześć rodzin strategii i dotychczasowy profil są zachowane; nie ma promocji odrzuconych strategii. Limity pozostają 0,5% / 1,5% / DD 5% / x5, obowiązkowe SL/TP, Emergency i ochrona przed duplikatami. REAL jest trwale blokowany; brak AI Lab/uczenia/updatera.

Zamknięcie karty **nie jest STOP**. Finansowy STOP/pauza, AWARYJNY STOP i zamknięcie procesu mają różne skutki. Przed wyłączeniem aplikacji użyj właściwego polecenia i sprawdź faktyczne pozycje. Stary tekstowy panel/Emergency jest dostępny Operatorowi również przy błędzie źródła Naval; samo zamknięcie procesu nie potwierdza zamknięcia pozycji.

Wszystkie listenery aplikacji są tylko `127.0.0.1`. Nie wystawiaj portów na LAN/Internet, nie zmieniaj zapory/routera w celu ich publikacji. cTrader Desktop + ApexBridge pozostają osobną lokalną ścieżką; nie uruchamiaj dwóch mostów na jednym koncie. Żadne rzeczywiste konto, prywatny broker, transakcja DEMO/LIVE, sprzętowy GPU ani rentowność nie są zaakceptowane przez ten kandydat. Rzeczywista transakcja DEMO wymaga osobnej wyraźnej zgody.

W `apex-build.json` pozostają `windowsRuntimeTested=false`, `brokerTested=false`, bo ZIP jest zapieczętowany **przed** smoke.
