# Task2 public-data refresh API (no trading/UI integration)

## Canonical strategy input

`OkxAdvisoryCanonicalData.Serialize(NavalSeries, DateTimeOffset cutoff) -> byte[]` exports the **actual** strategy-consumed `NavalSeries`. `market_contract.canonical_snapshot(pair, cutoff, bars) -> bytes` emits identical compact ASCII JSON; `dataset_digest(bytes)` is lowercase SHA256. `decode_snapshot(bytes,pair,cutoff)` rejects noncanonical bytes. The source-linked StrategyExport harness invokes the actual `OkxPublicMarketFeed.ReadSeriesAsync` against an unsigned HTTP fixture, verifies the exact EEA URL/query, excludes the current partial candle and compares emitted bytes with Python (28-significant-digit decimals).

Schema `apex-strategy-candles-v1` field order: Schema, Instrument, BaseCurrency, QuoteCurrency, Source, Bar, PriceBasis, VolumeUnit, AsOfUtc, Bars. Source = `OKX EEA public /market/candles 1Dutc`; PriceBasis = trade; VolumeUnit = exact base; quote EUR. Each chronological row is seven **strings**: Unix opening milliseconds, O,H,L,C,base volume, `1`. Decimal strings use plain invariant notation, remove insignificant fractional zeros, never float/exponent. Up to 300 candles, contiguous UTC days, latest completed bar ends at cutoff; 200 minimum. Unused OKX response columns 6/7 are not consumed by the strategy and do not enter the canonical seal. This is equality of consumed content, not raw HTTP-body equality. Native numerical tools necessarily use their original pandas floating-point computations **after** verifying the lossless input seal; do not claim their numeric outputs are decimal-exact.

The C# serializer refuses a series with another source/quote/basis/window. Python does not refetch a second endpoint or choose another candle window. Caller must pass the canonical actual consumed series; a Python-only snapshot is not production strategy parity proof. All-pair fixture graph data is synthetic, not an actual-market observation.

## Coordinator and accounting

`Budget(path,clock).reserve(day,pair,tool,deadline,digest) -> Reservation | Refusal` persistently claims one automatic attempt per UTC day/pair/tool. `reserve_request(attempt,milliseconds)` commits each request BEFORE inference. SQLite immediate transactions and FULL synchronous commits serialize **one shared ledger for all pairs/tools**. Cap = 48 supervised requests and 900000 **reserved milliseconds** per UTC day. Each slice is 1..120000ms and must fit the attempt/day deadline. Every slice is permanently charged in full, **no refunds even on fast success**. A crash leaves charged request/time and uncertain observed usage, and the attempt cannot automatically repeat. This conservative policy can exhaust earlier than 900 actual seconds. `usage()` exposes reserved and separately observed wall milliseconds, unknown requests and null provider-internal retries; these are not token, billing or provider-retry claims. Genuine transport uses a six-second margin for cancellation/IPC inside its outer supervised process deadline. OS scheduling and provider-internal execution after interrupt are not measurable billing guarantees.

`Supervisor(root,RuntimeContract,...).refresh(pair,cutoff,datasetBytes) -> ReportPairStatus` runs both genuine upstream graphs in separate pinned processes, using one immutable canonical file per attempt. Runs on caller's background lane; no trading callback/network on trading lane. Reuse matching completed generations; changed same-day content returns CANONICAL_PARITY_MISMATCH before graph work. Missing/corrupt publication does not erase spent attempts. Partial successful results persist before starting the other graph. Pair refresh lock prevents concurrent graph/publication races; the daily budget is shared. `close()` cancels, drains the refresh lane and releases storage admission; the application owns startup/day-change invocation and must stop invoking after close. There is no OS task/autostart here.

Native worker launch validates Task1 runtime pins; no cwd/HOME constants, no Linux venv copy, no broker/auth inheritance. Environment scrubbing is NOT an OS sandbox. Native Windows store admission reuses source-linked WindowsPathSecurity: root ACL at creation, ancestor/root validation, then **all existing descendants inspected before SQLite initialization**. Every traversed directory is validated and held with a native no-delete-sharing handle until close; fresh service-created directories are created privately and leased before use. Pre-refresh scanning rejects unsafe children added since initial admission before any attempt/budget transaction. Existing files must have a private DACL, expected type and a single link. The main DB and per-pair lock retain stable file leases; SQLite journal/WAL/SHM are inspected before transactions without preventing SQLite from deleting them. Report reads hold scoped native file handles; atomic publication inspects its target without holding the old CURRENT across replacement. Unsafe ACLs, junctions/reparses, hardlinks and wrong types refuse, never repair or resolve away identity. `Supervisor` explicitly supplies its `StoreLease` to the low-level Budget/report/lock primitives; any future native consumer must likewise supply that lease (their unleased defaults are for isolated offline tests, not a native storage boundary). The engineering guard DLL is built by StrategyExport; final installer/production-host packaging is a later task. `store_guard` accepts its explicit path. Missing helper fails closed on Windows.

Production inference owns an explicit local Hermes profile root (`hermes_home`; HERMES_HOME is its `hermes` child), never an upstream HOME; it must already be enrolled on exact gpt-6.1-sol/openai-codex. Canonical safe tool-free session route is checked before AND after, one turn, no fallback. Application tool JSON is a separate closed protocol. Prompt bound widened from 16000 to 250000 characters after retained real upstream payload lengths showed 48008+; no truncation. Response <=16000 characters, IPC <=1MiB line / 8MiB stream / bounded queue, unknown tools and schema fields refuse. Task2 fixtures never enroll/copy auth or call a provider.

## Immutable report pair for next C# consumer

Old strict `apex-advisory-v1` schema and C# shadow parser are unchanged. Each generation at `<root>/<PAIR>/generations/<32 lowercase hex>/` contains `vibe-trading.json`, `tradingagents.json` (unchanged closed v1 fields), matching `*-native.json` with native result/failure, and `manifest.json` (`apex-advisory-pair-v1`). Atomic `CURRENT.json` (`apex-advisory-pointer-v1`) names generation and manifest SHA256. Consumer must bound/strictly parse pointer, validate generation syntax before path construction, verify manifest/hash then both report/native hashes and exact pair/source/model/provider/canonical digest/cutoff/expiry. Never read two mutable flat report files independently. Use existing native private-store admission for the lifetime of reads. No consumer or active admission is added in Task2.

Manifest fields: Schema, Generation, Instrument, DatasetSha256, AsOfUtc, ExpiresUtc, Inference (`genuine` or `fixture`), Tools. Tool record: ReportSha256, NativeSha256, OriginalRecommendation (null if failed), MappedRecommendation (null if failed), State (`completed`/`failed`). Original Buy/Overweight -> BUY; Hold -> WAIT; Underweight/Sell -> SELL. Vibe native BUY/WAIT/SELL preserved. Published failure states survive restart. Fixtures retain native/mapped outputs in the manifest but **v1 Status remains unavailable and Recommendation WAIT**; a future active consumer must reject Inference!=genuine. Missing/stale/disagree advice will veto only new buys in Task4, not yet implemented.
